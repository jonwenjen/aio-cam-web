# M1 核心引擎與暗房最小版 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 如果 Claude Code 沒有安裝 superpowers，照 `RUN-IN-CLAUDE.md` 的流程一次做一個 Task。

**Goal:** 做出可上線的 M1：在瀏覽器匯入 iPhone 照片 → 一鍵自動調整並推薦最適合的發色（spec §7.5，N41–N43）→ 套 7 組（暫定）發色 → 存成保留 HDR 增益圖、P3、EXIF 的 JPEG，並有輸出隱私開關、WebGPU／WebGL2／CPU 三條一致的算圖路徑、PWA 離線。

**Architecture:** 純 ES modules、無建置工具。`io/` 只處理位元組（JPEG／TIFF／HEIC 結構），`engine/` 只處理像素（一個單 pass shader：解碼 → 曝光與白平衡 → 33³ LUT → 暗角 → 編碼 → 顆粒），`looks/` 把配方轉成 `RenderParams`（所有色彩科學都在 CPU 產生 LUT，GPU 只查表）。預覽與存檔共用 `engine.render`；存檔時直接在 shader 內轉回原存檔方向，增益圖逐位元組照抄（B 法）。

**Tech Stack:** HTML/CSS/JS（ES2023 modules）、WebGPU（WGSL）、WebGL2（GLSL ES 3.00）、IndexedDB 不在 M1 範圍；測試用 Node 26 `node --test`、headless Chrome + CDP（Node 內建 WebSocket）、`exiftool` 13.55、Swift（Apple ImageIO／CoreImage 量測工具）、devDependency 只有 `culori`（ΔE2000，只在測試）。

**Spec:** `docs/superpowers/specs/2026-10-26-aio-cam-web-design.md`（v0.5）。M1 對應 §1.2 的 S1–S4、S6、S7、S16、S20；§5、§7.5（N41–N43）、§8、§10、§12、§13、§14。

## Global Constraints

- 純 ES modules，**不用打包或轉譯工具**；`index.html` 直接載入 `js/main.js`。`package.json` 只放測試腳本與 devDependencies（§5.1）。
- 所有處理在本機，**不上傳任何資料**；沒有分析或追蹤程式（§12）。
- 品牌名稱、底片型號**只能出現在 `docs/`**，不出現在介面、程式識別字、檔名、i18n、輸出檔中繼資料（§1.1）。`tools/check-brands.mjs` 強制檢查。
- 工作色域固定 Display P3；輸入是 sRGB 時先轉 P3（§8.2）。
- 隨機效果用座標雜湊，**同參數必得同結果**（§8.2）。
- HDR 只用 B 法：維持原存檔方向，增益圖逐位元組照抄；不帶入 `APP10:AROT`；存檔後自我檢查，失敗就改存 SDR 並告知（§8.3.2）。**禁止讓瀏覽器解碼增益圖**（§4）。
- M1 沒有會改變尺寸的編輯，所以 JPEG＋增益圖輸入一律輸出 HDR；HEIC／DNG 輸入在 M1 一律輸出 SDR，HEIC 第一次時提示「想保留 HDR：設定 → 相機 → 格式 → 最相容」（§8.3.5）。
- 輸出：JPEG 品質 0.92；檔名 `AIO_YYYYMMDD_HHMMSS_<發色代號>.jpg`（§8.4）；EXIF 加 `Software=AIO Cam Web <版本>`，配方寫進 XMP（§8.4）。
- 隱私開關三選一，**預設「保留全部」**，存檔面板一直看得到目前選項（§8.4、N03）。
- 不提供 `<input capture>`；匯入用 `<input type=file accept="image/*" multiple>`（§8.1）。
- 自動推薦全部在本機計算，不用模型、不連網；介面用「自動」「推薦」，不叫 AI（§7.5）。「匯入時自動套用推薦」預設**關閉**。
- 介面固定深色；觸控區 ≥ 56pt；常用控制不收進選單（§11、使用者偏好：控制要放在顯眼容易按到的地方）。
- 第三方程式碼只用 MIT／Apache-2.0／BSD／ISC／CC0，記錄在 `docs/licenses.md`（§5.4）。
- 驗收門檻（照抄 §1.2）：
  - S1：48MP 匯入 → 套發色 → 存檔 ≤ 2.0 秒（iPhone 18 Pro Max）。
  - S2：「原色」輸出 HDR 峰值與原圖相差 ≤ 5%，超過一般白色的像素比例相差 ≤ 3 個百分點。
  - S3：EXIF 拍攝時間、時區、GPS、機型、鏡頭、光圈、焦段與原圖完全一致。
  - S4：P3 純綠 (0,1,0) 存檔後讀回誤差 ≤ 1/255。
  - S6：WebGPU、WebGL2 對 CPU 參考：ΔE2000 平均 ≤ 0.5、最大 ≤ 2.0（10 張固定測試圖 × 全部發色）。
  - S7：只有 WebGL2 時能跑完整流程且無錯誤。
  - S20：自動調整——好照片 |EV| ≤ 0.2、|Δ色溫| ≤ 200K；40 張劣化圖曝光殘差平均 ≤ 0.3 EV、色溫殘差平均 ≤ 400K；結果確定；分析＋計算 ≤ 50 ms（iPhone）。
  - S16：「去除位置」後找不到任何 GPS 標籤；「去除全部」後只剩方向與色彩描述檔（必要時加 Apple HDR 參數 MakerNote tag 33、48）；兩者 HDR 照樣保留。
- **M1 的發色是暫定版**：7 組原版發色（`asshot` `natural` `hiyori` `streetscape` `heritage` `clearview` `chiaroscuro`）照 §9.2 的起始值實作；金樣本定版在 M3。M1 的 LUT 模型支援 `wb`、`tone`、`color.saturation/vibrance`、`hsl`、`grade`；`tone.exposure`（EV，−3…+3，v0.4 補進 §9.1）也支援。其餘配方欄位（`curve`、`chrome`、`paper`、`mono`、`tintBar`、`skinProtect`、`detail`、`filter`、`effects`、`keepColor`）解析並保存，但 M1 引擎忽略。
- 內部像素：來源 `rgba8unorm`（P3 sRGB 曲線編碼），shader 內以 f32 計算，LUT 為 `rgba32float` 3D 貼圖（檢查點 A 決定：f16＋硬體濾波讓接近中性的像素 ΔE 達 2.17，超過 S6）。shader-f16 最佳化延後（不影響 M1 驗收）。

## Review Focus

1. **Safari 分享面板需要使用者手勢**：48MP 處理 1–2 秒後呼叫 `navigator.share` 可能被拒（`NotAllowedError`）。預期：自動改顯示一顆大的「分享／儲存」按鈕，按一下就開分享面板，不算錯誤。→ Task 12 `deliver` 測試、Task 15 介面測試。
2. **使用者在分享面板按取消**（`AbortError`）：不顯示錯誤、不重做處理，按鈕仍可再按。→ Task 12、Task 15。
3. **沒有增益圖、非 iPhone、sRGB、灰階 JPEG**：照常輸出 SDR，sRGB 轉成 P3，不報錯。→ Task 12、Task 13（`plain_srgb.jpg`、`gray.jpg` fixture）。
4. **EXIF 編輯後超過 APP1 上限 65,533 bytes**：先拿掉縮圖（IFD1），仍超過就改用「去除全部」等級的最小 EXIF 並告知。→ Task 2、Task 3、Task 13 測試。
5. **方向 5–8（直拍）的 HDR JPEG**：輸出 SOF 尺寸必須等於原存檔尺寸、EXIF 方向不變、增益圖位元組完全相同；畫面看起來仍是正的。→ Task 8（CPU 方向表）、Task 12（`gm_gps_rot6.jpg`）。

### 釘死的數學（CPU 與 GPU 必須逐式相同）

```
decode8(v)  = P3 使用 sRGB 傳遞函數：c=v/255; c<=0.04045 ? c/12.92 : ((c+0.055)/1.055)^2.4
encodeOETF(x)= x<=0.0031308 ? 12.92x : 1.055x^(1/2.4)-0.055
enc(x)      = log2(1 + 255·clamp(x,0,1)) / 8          // LUT 取樣座標，[0,1]→[0,1]
dec(e)      = (2^(8e) − 1) / 255
LUT 內容     = enc(輸出線性值)；取樣：texel 座標 = enc·(N−1)，三線性內插；GPU 也用 textureLoad／texelFetch 讀 8 個格點、在 shader 內以同樣權重手動內插（不用硬體濾波）
像素流程     = lin = decode8(src) · 2^exposureEV · wbGains
              lin = dec( trilinear(LUT, enc(lin)) )
              lin = lin · (1 − vignette.amount · smoothstep(0.35, 1.0, r))
                    r = |p − c| / |(W/2, H/2)|，p = 轉正座標的像素中心，c = 畫面中心
              e   = encodeOETF(lin)
              e   = e + grain.amount · 0.12 · n · 4·Y·(1−Y)        // Y = 0.2290e_r + 0.6917e_g + 0.0793e_b（P3 亮度係數，作用在 e）
              out = round(clamp(e,0,1)·255)
顆粒雜湊     hash(x,y,s): h = (x·0x8da6b343) ^ (y·0xd8163841) ^ (s·0xcb1ab31f)（u32 乘法溢位截斷）
              h ^= h>>16; h *= 0x7feb352d; h ^= h>>15; h *= 0x846ca68b; h ^= h>>16
              h2f(h) = (h>>8)/16777216·2 − 1
值雜訊       vnoise(p, cell, s): q = p/cell；i = floor(q)；f = q−i；w = f·f·(3−2f)
              bilerp(h2f(hash(i)), h2f(hash(i+(1,0))), h2f(hash(i+(0,1))), h2f(hash(i+(1,1))), w)
n            = (1−roughness)·vnoise(p, cellPx, seed) + roughness·vnoise(p, max(1,cellPx/2), seed+1)
              chroma=true 時 R、G、B 各用 seed、seed+2、seed+4（G、B 的細層再 +1）
```
- `p` 一律是**轉正座標**的整數像素索引（不是存檔座標），所以直拍照片的顆粒與暗角跟畫面方向一致。
- JS 版用 `Math.imul` 與 `>>> 0`；WGSL 用 `u32`；GLSL 用 `uint`（`highp`）。

### 方向表（存檔座標 (sx,sy) → 轉正座標 (ux,uy)）

存檔尺寸 `Ws×Hs`；方向 5–8 時轉正尺寸 `W=Hs, H=Ws`，否則 `W=Ws, H=Hs`。

| EXIF | ux | uy |
|---|---|---|
| 1 | sx | sy |
| 2 | Ws−1−sx | sy |
| 3 | Ws−1−sx | Hs−1−sy |
| 4 | sx | Hs−1−sy |
| 5 | sy | sx |
| 6 | Hs−1−sy | sx |
| 7 | Hs−1−sy | Ws−1−sx |
| 8 | sy | Ws−1−sx |


```
  contrast  c: y = y + c·(3y² − 2y³ − y)

  shadows   s: y = y + 0.6·s·y·(1−y)²

     w_i = max(0, 1 − |Δh_i|/45)（Δh 取最短角距）；W = Σw_i，W>1 時全部除以 W

  grade：Lb = clamp(L − 0.2·balance, 0, 1)；ws=(1−Lb)²、wh=Lb²、wm=2Lb(1−Lb)
     (a,b) += Σ_{s,m,h} w·strength·0.06·(cos hue, sin hue)
  轉回線性 P3；若任一通道 <0 或 >1：保持 L、h，對 C 做 8 次二分縮小到全部落在 [0,1]
```
