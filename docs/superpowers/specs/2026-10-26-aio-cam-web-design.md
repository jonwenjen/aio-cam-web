## 1. 目標

做一個**網頁版、免安裝、不上傳**的「各牌發色」相機與暗房：

1. **功能對等**：AIO Camera 的每項功能都列在 §2 對照表。網頁做得到的照做；做不到的，給出明確替代方案，或註明「不做」與原因。
2. **超越原版**：見 §3。重點是保留 HDR、48MP、完整 EXIF，配方可分享，支援 `.cube` LUT，跨平台，免費。
3. **iPhone 18 Pro Max 體驗最好**，其他手機依能力降級後仍可使用（§10）。

### 1.1 不做的事
- 不做帳號、雲端、伺服器端處理；照片永遠不離開裝置。
- 不做 App Store 原生 App。
- 不收費、不做試用期。
- **相機品牌名稱只出現在 `docs/` 的註記**，不出現在介面文字、程式碼識別字和輸出檔中繼資料（§9.2）。底片型號（如 Portra、Classic Chrome）同樣只出現在 docs。

## 4. 平台事實（實測，非推測）

全部來自 iPhone 18 Pro Max／iOS 27.0.1／Safari 實機。

| 主題 | 實測結果 | 設計結論 |
|---|---|---|
| 解碼 | `createImageBitmap` 解 48.8MP JPEG／HEIC／DNG，250–500 ms | 不需自寫解碼器（ProRAW 沖洗例外） |
| 精度 | 所有格式解碼後都是 8-bit；DNG 解出的是內嵌 8-bit 全尺寸預覽 | 內部用 float16；RAW 精度只能走 F41 |

| WebGPU | `shader-f16`、`float32-filterable`；單一緩衝區上限 1 GiB；48MP 逐像素運算 5–7 ms | 主引擎 |
| WebGPU 顯示 HDR | `rgba16float` + `display-p3` + `toneMapping: extended` 有效，目視比一般白更亮 | 可做 HDR 預覽 |
| WebGL2 | 可設 Display P3 輸出；無 float16 畫布 | 退回路徑，只有 SDR |
| 色域 | 2D 畫布 P3；JPEG 帶 Display P3 描述檔，讀回誤差 1/255 | 全程 P3 |
| 編碼 | `toBlob`：JPEG、PNG、HEIC、AVIF；無 WebP、JXL | F42 |
| HDR（JPEG） | 「最相容」格式含 2856×2142 單通道增益圖；Apple 與 ISO 21496 兩種 HDR 資料並存 | §8.3 |

### 5.3 單元邊界

| 單元 | 輸入 → 輸出 | 不負責 |
|---|---|---|
| `io/import` | `File` → `SourceImage { bitmap, storedSize, orientation, exif, icc, gainMap?, depth?, raw?, kind }` | 色彩處理 |
| `looks/*` | 配方 → `RenderParams`（數值參數 + LUT） | GPU |
| `engine/*` | `(畫面來源, RenderParams, 目標)` → 像素 | 檔案格式 |
| `io/export` | `(處理結果, SourceImage, 輸出選項)` → `File[]` | 色彩處理 |
| `capture/modes/*` | 相機串流 + 模式設定 → 幀序列或單一影格 | 套發色（交給 engine） |
| `ml/segment` | 影格 → 低解析度主體遮罩 | 合成（交給 engine） |

`engine` 不認識檔案，`io` 不認識 GPU。預覽和存檔共用同一個 `engine.render`，只差解析度，**看到什麼就存到什麼**。

## 6. 拍攝模式

模式轉盤順序：**底片卷｜隨拍｜拍照（預設）｜人像｜夜間｜長曝｜錄影**。左右撥動切換，記住上次模式。網址參數 `?mode=` 可直接開啟指定模式（N40）。

### 6.1 共用控制
- **開啟相機**：`getUserMedia({video:{facingMode:'environment', width:{ideal:4032}, height:{ideal:3024}}})`。
- **倍率鍵** 0.5／1／2／4／8× + 轉盤式連續變焦：只設 `zoom`，**不可**同時帶 width/height 約束（實測過的坑）。
- **預覽**：每幀（`requestVideoFrameCallback`）→ WebGPU `importExternalTexture` → 套發色。預覽解析度＝螢幕像素。
- **快門**：把 `<video>` 當下影格複製成獨立 3024×4032 紋理（`copyExternalImageToTexture`），再以全解析度處理一次。不用 `takePhoto`。
- **數位曝光補償** ±2 EV：點畫面任一處，以該處 9% 面積亮度推算 EV，使該區趨近 18% 灰；長按鎖定（AE-L）。介面標明「數位」。
- **測光表**：顯示目前畫面相對 18% 灰的 EV。
- **白平衡鎖定**：硬體 `whiteBalanceMode`。
- **補光**：torch 開關。
- **計時器**：3／10 秒，倒數閃 torch（3：一次、2：一次、1：三次）。
- **其他**：網格、水平儀、畫幅比例、前後鏡頭。所有設定保存。
- **拍攝輔助**（M2）：
  - 網格另有黃金比例、對角線、中心十字；焦段框線 28／35／40／50／85mm（可選「依框線裁切」）；IG 4:5 與 9:16 安全區疊層（N09）。
  - 即時直方圖、過曝斑馬紋（門檻 75–100%）（N05）；對焦峰值與局部放大（N29）。
  - 3D 水平儀：橫滾＋俯仰，手機接近水平時切換為氣泡十字（N10）。
  - 晃動指示：依陀螺儀顯示穩定度，夜間、長曝模式預設開啟（N24，M7）。
- **前鏡頭螢幕補光**（N11）：快門瞬間整個螢幕變暖白，維持到擷取完成。
- **雙重曝光**（N15，M4）：開啟後取景器疊上前一張半透明殘影；第二張拍完以平均、變亮或濾色混合。
- **藍牙鍵盤遙控**（N33，M10）：Space／Enter 觸發快門。
- **對焦框調色盤（F18）**：點畫面後旁邊浮出小型色彩×影調盤，只在本次使用有效。
- **權限與錯誤**：見 §13。

### 6.2 拍照
套目前發色、濾鏡、浮水印，輸出 12MP。即時拍攝沒有增益圖，輸出 SDR。
- **拼版子模式**（N16，M4）：半格雙聯（兩張直幅並排成 3:2，中間細黑縫並印片號）、人生四格（2×2 或 1×4 直條）。依序自動拍，可設定間隔。輸出 SDR。
- **連拍**（N12，M7）：按住快門連取影格，另有快門前 1 秒預錄緩衝；自動以 Laplacian 變異數挑最清楚的一張，其他可在沖洗簿保留或丟棄。也可把連拍做成正反播放的 GIF／短循環（N36，M6）。

### 6.2a 底片卷（N14，M5，需先完成 P8）
- 開新卷時選張數（12／24／36）、發色或相機組合（§9.4），之後整卷固定。
- 拍攝時**看不到結果**，只顯示剩餘張數；拍完最後一張，或到設定的沖洗時間（立即／1 小時／隔天早上），才能「沖洗」。
- 未沖洗的照片以原始影格（JPEG q0.95）加配方暫存在 OPFS；沖洗時套用配方輸出，完成後刪除暫存檔。這是 §12「不存全尺寸照片」唯一的例外，仍然完全不上傳。
- 開新卷前檢查 `navigator.storage.estimate()`，空間不足就先警告；同時要求 `navigator.storage.persist()` 降低被系統清除的風險。
- 沖洗後可輸出整卷印樣（N21）。驗收見 S18。

### 6.3 隨拍
- 畫面只有快門和變焦拉桿。拉桿標出各鏡頭焦段，經過時停頓，雙擊回 1x。
- 拍完在 256px 縮圖上分析場景：平均亮度、動態範圍、色溫估計、飽和度；膚色比例（YCbCr 範圍）、天空比例（上方藍區）、綠色比例；低光判斷。
- 依規則表給全部發色、濾鏡（含「不加濾鏡」）、顆粒、光暈加權重，以**拍攝時間為種子的亂數**抽選：每張不同，但可重現。
- 抽到的組合寫進沖洗簿和檔案 XMP。介面稱「場景分析」，不叫 AI，因為沒用模型。

### 6.4 人像（M8，需先完成 P3）
- 每幀用分割模型算 256×256 主體遮罩，放大後混合：背景虛化 + 膚色區磨皮（F34）。
- 存檔時以全解析度重算遮罩並做邊緣細化。
- 不支援時只提供美顏、不做虛化。

### 6.5 夜間（M7，需先完成 P4）
- 連取 8–16 幀 12MP（約 0.3–0.5 秒），顯示進度圈與「請保持穩定」。
- 以 256px 縮圖的 Laplacian 變異數挑最清楚的一幀當參考幀（G06）。
- 先用縮小亮度圖做相位相關求整體位移，再分塊修正局部位移（演算法參考 HDR+ 論文，§5.4）。
- 去離群值後平均，輕度降噪，再套發色。
- **星空**（N34）：同一流程延長到 64–256 幀，只適用月亮與亮星；搭配紅光夜視介面。

### 6.5a 間隔拍攝／縮時（N13，M7，需先完成 P9；輸出 MP4 另需 P2）
- 設定間隔（1–60 秒）與張數；期間用 Wake Lock 防止螢幕關閉。頁面必須留在前景，介面明確提示。
- 輸出：各張照片，或合成縮時 MP4。

### 6.6 長曝（M7）
- 1–30 秒，提示使用腳架。
- **平均**：絲絹流水；**最亮**：光軌。
- 全程在 GPU 累加紋理上運算，記憶體用量固定。

### 6.7 錄影（M6，需先完成 P2）
- Canvas `captureStream` + 麥克風 → `MediaRecorder` 錄 MP4（H.264）。若不穩，改 WebCodecs + 自寫 muxer。
- 目標 1080p30；4K 依實測決定。
- 錄影時套發色，可疊日期（F24）；錄影中按快門另存照片（F22）。
- 中途切到背景：結束目前段落 → 回來後接著錄下一段 → 按停止時合併成單一 MP4（F23）。
- **錄影輔助**（N25）：音量表（WebAudio AnalyserNode）、2.39:1 與 9:16 框線、錄影時間、剩餘空間（`storage.estimate`）。
- **監看工具**（N30、G05）：波形、向量示波器（含膚色線）、假色，錄影與暗房都可開。

## 8. 匯入與輸出流程

### 8.1 匯入
1. `<input type=file accept="image/*" multiple>`，不加 `capture`。
2. 讀檔頭判斷格式。
3. 解析中繼資料：
   - JPEG：EXIF、ICC、MPF、增益圖與深度圖的位元組範圍；
   - HEIC／DNG：掃描 TIFF 區塊取得 EXIF，原始位元組保留。
4. `createImageBitmap` 解碼，取得已轉正像素。
5. 記錄 `storedSize`（JPEG SOF 尺寸）與 `orientation`，供輸出轉回原存檔方向。

### 8.2 色彩流程
```
8-bit P3 ─解碼─▶ float16 線性 P3
  → 幾何（裁切、拉直、透視、鏡頭校正）
  → 曝光、白平衡偏移 → 3D LUT（發色＋沖印紙＋HSL＋曲線＋色輪烘在一起，33³，對數編碼空間取樣）
  → 色彩×影調盤 → 偏色條 → 膚色保護 → 濾鏡 → 局部調整 → 清晰度、銳利度、去霧
  → 保留色彩／遮罩混合 → 直閃 → 光暈金字塔（紅暈、黑柔焦、光暈）→ 漏光 → 暗角 → 顆粒
  → 浮水印、邊框 → P3 sRGB 曲線編碼 → 8-bit
```
- 工作色域固定 Display P3；輸入是 sRGB 時先轉 P3。
- 顆粒、漏光等隨機效果都用座標雜湊產生，同參數必得同結果（方便測試）。

### 8.3 HDR 保留

**8.3.1 原理**：增益圖記錄「HDR ÷ SDR」的比例。只改 SDR 主圖顏色、不改尺寸時，照抄原增益圖仍是合理的 HDR。實測 B 法峰值誤差 0.8%。

**8.3.2 規則（B 法）**：原圖是 JPEG、含增益圖，且編輯**沒有改變尺寸**時，才輸出 HDR。
1. 處理用轉正後像素；存檔時轉回原存檔方向，尺寸＝`storedSize`。
2. 重組順序：
   ```
   SOI → 原 EXIF（方向不變）→ 原 XMP（加上配方）→ 新 ICC（P3）
     → 新 MPF（重算偏移）→ 原 ISO 21496 區段 → 新主圖
     → 原增益圖（逐位元組照抄）
   ```
3. 不帶入 Apple `APP10:AROT` 區段（私有資料、用途不明；實測拿掉後 HDR 正常，記在 R3）。
4. 存檔後重新解析輸出做自我檢查：MPF 指得到增益圖、尺寸一致。失敗就改存 SDR 並告知。

**8.3.3 會改變尺寸的編輯**（加邊框、裁切、旋轉、拉直、透視、社群尺寸、拼版）——M4 前先完成 P1：
- 驗證：拿掉增益圖 ICC 後以 `colorSpaceConversion:'none'` 解碼，數值是否與原始值完全一致。（A 法失真的推測原因是增益圖帶 PQ ICC，被做了色彩轉換。）
- 通過：增益圖與主圖在 GPU 上做相同幾何變換，邊框區增益設 1.0（不增亮）。
- 不通過：改用 JS 自行解碼 baseline JPEG。
- 驗證通過前，這類編輯一律存 SDR，並在存檔鈕旁標示「此編輯會輸出 SDR」。

**8.3.4 HDR 預覽**（M4，與 P1 同解）：在 WebGPU HDR 畫布上，shader 內套增益圖顯示。在此之前預覽只有 SDR，角落加「HDR」標籤表示輸出會保留 HDR。

**8.3.5 HEIC**（M9，需先完成 P6）：取出 `auxC` = `urn:com:apple:photo:2020:aux:hdrgainmap` 的 HEVC 圖塊；能解碼就輸出含 HDR 的 JPEG。在此之前 HEIC 存 SDR，並一次性提示「想保留 HDR：設定 → 相機 → 格式 → 最相容」。

### 8.4 輸出
- **格式**：JPEG（預設，品質 0.92；48MP 約 300 ms）。M9 加 HEIC、AVIF 選項，以及延遲載入的 MozJPEG、WebP、JXL（G07，需 P13）；HDR 保留只限 JPEG（MozJPEG 主圖也可，增益圖照抄）。
- **社群尺寸預設**（N02，M4）：原尺寸／IG 4:5 1080×1350／3:4／1:1／限動 9:16（模糊或純色補邊）／自訂長邊。可存成自己的預設。
- **檔名**：預設 `AIO_YYYYMMDD_HHMMSS_<發色代號>.jpg`；M9 起可自訂範本（N28）。
- **存檔**：`navigator.share({files})` 開分享面板；不支援則下載。
- **隱私開關**（N03，M1）：每次存檔面板都看得到目前選項。
  - **保留全部**（預設）：EXIF 原樣保留，符合 S3。
  - **去除位置**：拿掉 GPS IFD 與 XMP 中的位置欄位，其他保留。
  - **去除全部**：只留方向、色彩描述檔與 HDR 必要區段（MPF、ISO 21496）；配方 XMP 也不寫。注意 Apple 自己的 HDR 參數存在 EXIF MakerNote（tag 33、48），去除後 HDR 只能靠 ISO 21496 區段；這點由 S16 實際量測確認，不成立就保留 MakerNote 中這兩個標籤。
  - 驗收見 S16。
- **EXIF**：
  - 匯入照片：原 EXIF 整段保留（隱私開關另有設定時除外）；HEIC 原圖的 EXIF 從 TIFF 區塊搬到 JPEG APP1；
  - 即時拍攝：自行產生（時間、時區、使用者授權時的 GPS）；
  - 一律加上 `Software=AIO Cam Web <版本>`，配方寫進 XMP；
  - M9 起可設定作者、版權、圖說，寫進 XMP 與 IPTC（N28）。

## 9. 發色、濾鏡與效果

### 9.1 配方資料格式
```json
{
  "v": 1, "name": "日和", "base": "hiyori", "intensity": 1.0,
  "wb": { "temp": 0, "tint": 0 },
  "tone": { "exposure": 0, "contrast": 0, "highlights": 0, "shadows": 0, "whites": 0, "blacks": 0 },
  "curve": { "rgb": [], "r": [], "g": [], "b": [] },
  "color": { "saturation": 0, "vibrance": 0, "pad": [0, 0], "chrome": 0, "chromeBlue": 0 },
  "hsl": { "red": [0,0,0], "orange": [0,0,0], "yellow": [0,0,0], "green": [0,0,0],
           "aqua": [0,0,0], "blue": [0,0,0], "purple": [0,0,0], "magenta": [0,0,0] },
  "grade": { "shadows": [0,0], "midtones": [0,0], "highlights": [0,0], "balance": 0 },
  "paper": "neutral",
  "mono": { "filter": "none", "tone": "neutral" },
  "tintBar": { "hue": 0, "amount": 0 },
  "skinProtect": 0.5,
  "detail": { "sharpen": 0, "clarity": 0, "dehaze": 0, "denoise": 0 },
  "filter": { "id": "none", "amount": 1.0 },
  "effects": { "halation": 0, "diffusion": 0, "glow": 0, "flash": 0, "leak": 0 },
  "keepColor": null,
  "grain": { "amount": 0.2, "size": 1.0, "roughness": 0.5, "format": "35mm", "chroma": false },
  "vignette": { "amount": 0.15 },
  "lensAware": true
}
```
- 每個數值都有上下限，超出就夾回；不認得的欄位忽略（往後相容）。
- 新欄位說明：
  - `tone.exposure`：數位曝光，單位 EV，−3…+3（暗房「曝光」滑桿；即時相機的數位曝光補償也寫在這裡）。
  - `curve`：控制點陣列 `[[x,y],…]`，最多 8 點（N17）。
  - `color.chrome`／`chromeBlue`：高飽和區亮度降低（約 sat²×0.15）以加深色彩、避免紅藍溢色；藍色另外加深。0–1。
  - `hsl`：每色相帶 `[色相偏移, 飽和, 明度]`（N07）。
  - `grade`：三向色輪，各為 `[色相角, 強度]`（N17）。
  - `paper`：沖印紙 `neutral`／`warm`／`cool`／`hard`（G08）。
  - `mono.filter`：`none`／`yellow`／`orange`／`red`／`green`；`mono.tone`：`neutral`／`sepia`／`selenium`／`cyan`／`warm`。只在黑白發色或黑白濾鏡下作用（N20）。
  - `grain.roughness`：顆粒粗細；`grain.format`：`half`／`35mm`／`120`，對應顆粒大小 ×1.4／×1.0／×0.6，再乘輸出短邊比例；`grain.chroma`：彩色顆粒。顆粒量依亮度分配，中間調最多。
  - `effects`：可疊加效果（§9.4）。
- 分享網址只寫與基礎發色不同的欄位：壓縮 → base64url → `#r=…`。目標一般 ≤ 200 字元，含曲線、HSL 時 ≤ 300 字元（S19）。
- 浮水印與邊框不屬於配方，另存為「浮水印設定」（§9.6）。
- **配方卡圖**（N22）：一張含樣張、主要參數與 QR 的分享圖。
- **匯入富士配方**（G02）：讀 Open Fuji Recipe 欄位的 JSON，近似轉成本版配方，介面標明「近似」。

### 9.5 保留色彩與保留主角
- **保留色彩**：點選畫面顏色，保留該色相 ±寬度，其餘轉黑白，邊緣羽化。
- **保留主角**：主體依遮罩保留彩色，背景轉黑白或套另一組發色。遮罩來源見 §6.4、§7.3；非人主體（寵物、物品）用顯著物件分割模型（u2netp，§5.4）。

### 9.6 浮水印與邊框
- **日期戳**：仿底片橘色七段數字；格式 `'YY MM DD`、`YYYY.MM.DD`、含時間；四角或自由拖曳。
- **自訂文字**：字型、大小（依短邊比例）、顏色、位置。
- **邊框**：拍立得（底部留白可寫字）、底片條（上下齒孔、片號與日期）、幻燈片（塑膠框 + 標籤文字）、純色框。
- **v0.3 新增邊框**（M4）：
  - **電影遮幅**：2.39:1 或 1.85:1 黑邊，可放字幕式日期。
  - **印樣**（N21）：整卷或多選照片排成 contact sheet，帶片號，用 512px 縮圖排版。
- **套用**：設定一次後每張自動套用（可關閉）；預覽即成品；錄影也能疊日期。
- **HDR**：加邊框會改變尺寸，依 §8.3.3。

### 11.1 發色呈現方式（取代字母徽章）

使用者決定不用原版的 F／R／L／O／N／C 字母徽章。改用以下三層，**畫面上一律不出現品牌名**：

1. **家族分組**：發色列依「中性／負片／正片／電影」四個家族分段，段與段之間有細分隔與家族名；濾鏡列另依「數位／玩具／底片／柔美／時尚／電影／黑白／實驗」分組。
2. **即時縮圖**：展開的發色選單（長按發色列）中，每格都是目前取景畫面套上該發色的 96px 縮圖，加上名稱。WebGPU 一次 pass 畫完所有格子；只有 WebGL2 的裝置把縮圖更新頻率降到每秒 5 次。
3. **色票＋特徵詞**：在取景區左右滑動切換時，畫面中央浮出約 1 秒的卡片：「名稱＋3 段色票（從 LUT 自動取樣的暗、中、亮色）＋2 個特徵詞」，例如：
   - 日和：柔・青影
   - 街景：冷・硬・粒
   - 經典：濃・深
   - 清透：藍・亮
   - 鎢絲夜：青・紅暈

色票由 `looks/swatch.js` 從 LUT 自動計算，所以自訂配方與匯入的 `.cube` 也有色票，調色改版後不會過期。特徵詞放在 i18n 檔，五種語系都要有。

「相機組合」（§9.4）入口另外用通用的底片罐插畫呈現，只用在組合，不用在單一發色。

## 12. 儲存與隱私
- 照片不上傳；全尺寸照片只在當下記憶體中，存檔一律走分享面板。
  - **唯一例外：底片卷**（§6.2a）。未沖洗照片暫存在 OPFS（裝置本機、App 專屬、不同步），沖洗後刪除；開新卷時明確告知。
- **沖洗簿**：IndexedDB 存 512px 縮圖 + 配方 + 時間 + 星等、旗標，最多 200 筆，可一鍵清除；不存全尺寸。可篩選、並排比較（N21）。
- IndexedDB 另存自訂配方、`.cube` LUT、浮水印設定、偏好設定、暗房編輯歷史（只存參數，不存像素）。
- **本機備份**（N26，M9）：以上資料可匯出成單一 `.aiocam` 檔（JSON + LUT），透過分享面板存到任何地方；再匯入即還原。沒有雲端。
- **輸出隱私開關**見 §8.4。
- Service Worker 快取 App 檔案；模型檔（M8）在第一次使用時才下載並快取。
- 第二支手機遙控（M10）只在同一 Wi-Fi 下點對點連線，連線資訊用 QR 交換，不經任何伺服器。
- 無任何分析或追蹤程式；GitHub Pages 本身的存取紀錄寫在說明頁。

## 13. 錯誤處理

| 情況 | 處理 |
|---|---|
| 相機權限被拒 | 顯示設定步驟，提供「改用暗房」 |
| 開相機失敗 | 自動重試 1 次（第一輪實測曾崩潰一次），再失敗顯示錯誤與重試鍵 |
| 無法解碼 | 告知格式，建議改「最相容」或換一張 |
| GPU 裝置遺失／記憶體不足 | 重建裝置，以 24MP 重試並告知 |
| HDR 自我檢查失敗 | 改存 SDR，提示「此張未能保留 HDR」 |
| 夜間／長曝晃動過大 | 剔除對不上的幀；可用幀 < 4 時改存單張並提示 |
| 錄影編碼失敗／空間不足 | 停止錄影，保存已錄段落 |
| 模型下載失敗 | 人像只提供美顏，並說明原因 |
| 配方網址無效 | 忽略並提示「配方連結無法讀取」 |
| 使用者取消分享 | 不視為錯誤 |
| 底片卷暫存被系統清除 | 開 App 時比對卷內張數，遺失時明確告知遺失幾張，不靜默略過 |
| 儲存空間不足（底片卷、錄影、縮時） | 開始前就警告；過程中不足時停止並保存已完成部分 |
| 方向感測權限被拒 | 水平儀改成只有網格，並說明如何重新授權 |
| Wake Lock 失效（螢幕仍關閉） | 間隔拍攝暫停，回到前景時提示已中斷並可接續 |
| 遙控連線中斷 | 兩端都顯示中斷，相機端快門照常可用 |

## 17. 風險

| # | 風險 | 對策 |
|---|---|---|
| R1 | 增益圖經瀏覽器解碼會失真（A 法） | P1 當門檻；未通過前存 SDR |
| R2 | 發色改變主圖後，照抄的增益圖可能讓高光過亮或偏色 | 每組發色以 S2 方法量測；超標就降低增益強度（需 P1 通過） |
| R3 | `APP10:AROT` 用途不明 | 已知拿掉無影響；照片 App 出現異常再研究 |
| R4 | iOS 改版改變相機 API 行為（例如開始支援曝光控制） | 一律以 `getCapabilities` 動態偵測，有支援就自動顯示控制 |

| R7 | 推測的品牌來源可能錯誤或引來商標問題 | 品牌名與底片型號只在 docs，並標註為推測或調色參考 |
| R8 | 模型、muxer 等第三方授權 | 依 §5.4 授權政策，全部記錄在 `docs/licenses.md`；模型授權另外檢查 |
| R9 | 發色從 7 組增加到 15 組，彼此太像、使用者分不出差別 | 金樣本階段做兩兩比較：任兩組在 10 張測試圖上的平均 ΔE2000 須 ≥ 3，否則合併或重新調色 |
| R10 | 底片卷暫存可能被 iOS 清除，造成照片遺失 | P8 當門檻；`storage.persist()`；開 App 比對張數並明確告知（§13）；未通過 P8 就不推出底片卷 |
| R11 | 隱私開關去除 EXIF 後，Apple 的 HDR 參數可能跟著消失 | S16 實際量測；必要時保留 MakerNote 中 HDR 相關標籤（§8.4） |
| R12 | 可疊加效果與光暈金字塔拖慢即時預覽 | S15 預算；超標時預覽改用更低解析度金字塔，存檔仍用全解析度 |
